## 用户的原话

「模板导入那页，点一下表头，程序就没了。」

不是排序排错，是进程直接退出，弹「未处理异常」。这页是导入汇总表模板、配置绑定行的入口，崩一次等于前面的配置全废。

## 先看异常文本

完整异常只有一句有用的话：

```
ArgumentException: 类型不具有名为"[内容]"的属性
```

`[内容]` 带方括号。方括号在 XAML 绑定里是索引器的写法，在属性名里不可能出现。所以第一个结论是：**某处把绑定表达式当成了属性名**。

翻这页的 XAML，列定义长这样：

```xml
<DataGridTextColumn Header="单元格" Binding="{Binding [单元格]}" />
<DataGridTextColumn Header="内容"   Binding="{Binding [内容]}" />
```

这是 `DataTable` 的常见写法。`DataTable` 的列是运行时才确定的，编译期没有对应属性，只能走 `DataRowView` 的索引器，而 XAML 里索引器的语法就是 `[列名]`。

到这里，两个事实对上了：XAML 里有 `[内容]`，异常说找不到名为 `"[内容]"` 的属性。

## 谁在做这件事

绑定本身不报错——不点表头时，这两列渲染得好好的。报错只发生在点表头。

点表头触发的是排序。WPF 的 `DataGrid` 排序不是「重排视图」，它做的是**给视图加一个 `SortDescription`**，而 `SortDescription` 的构造参数是**属性名**，来源是列绑定路径。

于是整条链路清楚了：

```
点表头
 → DataGrid 取该列的 Binding.Path
 → Path 是 "[内容]"（索引器语法，不是属性名）
 → new SortDescription("[内容]", Ascending)
 → 视图向 TypeDescriptor 要 "[内容]" 这个属性
 → 没有 → ArgumentException
 → 未处理 → 进程退出
```

一句话概括：**排序只认属性路径，索引器它当不了属性名。**

## 为什么只有点表头才炸

因为这两列平时走的是「取值」这条路：绑定引擎知道 `[内容]` 是索引器，能正确从 `DataRowView` 里取到那一列的值。

排序走的是另一条路：它不需要取值，它需要**一个能被反射/描述器识别的名字**。同一个字符串，在两条链路里的解释规则不一样。取值时它是索引器，排序时它必须是属性名。

这也解释了为什么这个 bug 拖了这么久才被发现：写代码时不点表头，测数据时也不点表头，只有用户想「排一下看看」的时候才踩到。

## 修法

修法只有一行：

```xml
<DataGrid CanUserSortColumns="False" ... />
```

这页的表本来也不该支持排序——它的行号就是绑定行号，`② 绑定行内容` 里第几行对应模板第几行，是位置信息，不是可以重排的数据。排序在这张表上既没有意义，还会破坏「行号」的语义。

如果确实需要排序，替代方案是把 `DataTable` 转成强类型集合（`List<RowItem>`），用真实属性名做列绑定，那样排序自然可用。代价是列变成编译期已知的，模板列名就不能自由配置了——对一个「模板列名由用户决定」的页面，这个代价不能接受。

## 同一页的另一个小改动

这轮还顺手把「绑定行号」的输入改了：

| 改前 | 改后 |
|---|---|
| 直接填数字的输入框 | `[−] [数字] [+]` 步进 |

看起来是审美问题，实际是使用节奏问题：调绑定行号时要一行一行往上试，每改一行就得看一次预览。步进按钮改一次刷新一次预览，滚轮也能微调，不用「选中文字 → 删掉 → 输入 → 失焦」四步。

顺带一提，这个控件加进来之后，「改一行刷一次预览」的频率上去了，才把上面那个点表头崩溃暴露得更快——**交互变顺手，会把藏在路径里的问题逼出来**。

## 验证

修完之后的检查清单很短，但每一条都必须点：

| 动作 | 期望 |
|---|---|
| 点每一个列表头 | 无异常、无弹窗 |
| 点数据行 / 单元格 | 选中状态正常 |
| 改绑定行号（步进 + 滚轮） | 预览即时刷新，行号与内容对应 |
| 关闭窗口再打开 | 已载入的绑定仍在 |

第一条必须「每一个表头都点」，因为 `CanUserSortColumns` 是表级开关，但列上还可以单独设 `CanUserSort`。这次只改表级就够，以后如果哪一列单独打开了排序，同样的坑会重新出现。

## 一条可复用的判断

凡是「**绑定路径是运行时字符串**」的场景——`DataTable` 索引器、动态属性名的 `PropertyDescriptor`、把 `Path` 拼出来的绑定——都要顺手问一句：还有谁会把这个字符串当**标识符**用？

WPF 里至少三个：排序（`SortDescription`）、分组（`GroupDescription`）、筛选（`CollectionViewSource.Filter` 里的属性名写法）。它们都不做「这是索引器」的特殊处理，都会直接把路径当属性名。

这次只炸了一个，是因为另外两条路径没被用到。
