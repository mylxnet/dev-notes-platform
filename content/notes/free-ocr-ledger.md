## 起因

想在屏幕上抠一段报错文字，常规路径是：截图 → 打开某个识别软件 → 粘贴 → 点识别 → 复制。五步，其中四步跟「识别」本身无关。

QuickOcr 把这个流程压成一步：托盘常驻，按 `Ctrl+Shift+O`，屏幕变暗，拖出区域，回车。结果显示在记事本里，同时已经进了剪贴板。识别默认跑本地的 Tesseract 5，不联网。

它自称「免费开源」。这四个字值得拆开算一遍账——不是为了挑刺，而是想知道：省下的钱，到底被挪到哪去了。

## 收入栏：四项都不带条件

先看拿到的部分，这部分是干净的：

| 项 | 许可 | 说明 |
|---|---|---|
| 程序代码 | MIT | 可改、可再分发、可商用 |
| 识别引擎 Tesseract 5 | Apache 2.0 | 通过 `Patagames.Tesseract` 封装调用 |
| 语言包 `chi_sim` / `eng` | `tessdata_fast` 仓库，Apache 2.0 | 模型数据这一栏经常是坑，这里没坑 |
| 运行时 | .NET 8 self-contained | 目标机器不需要另装 .NET |

模型数据的许可是最容易被跳过的一栏。很多「开源 OCR」的代码是 MIT，权重文件却是「仅限研究」，商用前才发现要重新找模型。QuickOcr 三栏都是宽松许可，这一项上没有留暗门。

## 支出栏一：226 MB

发行物有两个：

| 形态 | 体积 | 特点 |
|---|---|---|
| `QuickOcr_Setup.exe` | 约 226 MB | 自解压，解压到 `%LocalAppData%\QuickOcr\1.0.1\` 后自动启动 |
| `publish.zip` | 约 72 MB | 绿色版，解压即用 |

一个「框选屏幕文字」的小工具，226 MB 听着离谱。README 里给了原因，而且这条原因不是作者懒：

> 主程序依赖的 Tesseract 封装（InteropDotNet）通过 `Assembly.Location` 定位本地库目录，在 `PublishSingleFile` 模式下该值为空，会导致原生库加载失败。

也就是说，`dotnet publish -p:PublishSingleFile=true` 这条路走不通——原生 dll 拿不到自己的路径，加载就失败。于是主程序只能是「exe + 依赖 dll + `x64\` 原生库目录」的结构。真正做成单文件的反而是外面那层安装器：它把 `publish.zip` 嵌进去，运行时解压。

这是「免费」最常见的一笔隐藏支出：**体积换部署简单**。想让用户不装运行时，就得自带运行时；想自带运行时，就别指望单文件。

## 支出栏二：精度天花板

Tesseract 的边界很清楚，README 自己也写了：低分辨率、艺术字、复杂背景效果有限。

这里能看出一个设计判断。作者没有假装本地引擎够用，而是把「换引擎」做成了一等公民：

```
IOcrEngine（接口）
 ├─ TesseractEngine   本地，默认
 └─ HttpApiEngine     自定义 HTTP 接口
OcrEngineFactory 按设置返回实现
```

接口只有两个实现，但工厂 + 接口这一层让切换是「改一个设置」，不是「改一遍代码」。HTTP 那一路的约定也写得很具体：

| 项 | 约定 |
|---|---|
| 方法 / 编码 | `POST`，`multipart/form-data` |
| 图片字段 | 字段名 `image`，文件名 `capture.png` |
| 响应 | `{"text": "识别到的文字"}` |
| 超时 | 30 秒 |
| 鉴权 | 可选，附加自定义请求头（如 `Authorization: Bearer xxx`） |

还有一个细节：响应不是这个 JSON 结构时，**整个响应体被当作文字输出**。这不是偷懒，是把调试成本留在了自己这边——接口挂错地址时，用户至少能看到 HTML 报错页，而不是一行「识别失败」。

免费工具最容易省掉的就是这一层抽象：既然本地引擎免费，为什么要给「换引擎」留接口？答案在上面的表里：因为本地引擎有天花板，而天花板撞上的那天，用户不该被绑死。

## 支出栏三：第一次要联网

「离线可用」是有前提的。语言包不在仓库里，首次识别时缺失会自动拉 `chi_sim` + `eng`，约 3~4 MB；拉完缓存在 `%AppData%\QuickOcr\tessdata\`，之后就真的离线了。

拉不动的时候有一条明确的手动路径：从 `tessdata_fast` 取两个 `.traineddata` 放进 `tessdata` 目录。文档里写了「提示无法下载语言包」这个具体症状，而不是笼统的「请检查网络」。

「离线」在宣传语里通常被写成绝对状态。实际上它是一段时间之后才成立的状态：**第一分钟需要网络，之后不需要**。把这句话写进文档，比在标题里写「完全离线」诚实。

## 支出栏四：维护面

仓库结构很干净，但没有的东西同样清楚：

- 没有 `.sln`，只有两个 `.csproj`（主程序 + 自解压器）
- 没有 `doc/` 目录，`README.md` 一份 12 KB 承担全部文档
- 没有测试项目

代码量也不大，最大的单文件是 `Capture/OverlayWindow.xaml.cs`，12 KB 左右——框选遮罩的全部交互（拖拽、8 个手柄、选区外重画、多屏坐标）都在里面。

这是免费开源项目的常态：**文档、测试、CI 的投入永远排在功能后面**。它不构成缺陷，但意味着出了问题你得自己读代码。真要长期依赖它，这就是一笔要预提的成本。

## 没进账本的几处

反过来说，有些地方做得比「小工具」的预期好，而且都跟「免费」无关，纯粹是工程习惯：

| 细节 | 做法 | 为什么值得记 |
|---|---|---|
| 单实例 | Mutex + 命名管道，重复启动唤醒已有实例 | 托盘工具的常见毛病是一次开了三个 |
| 重复触发 | 识别任务串行锁，上一次没结束时新触发直接丢弃 | 连按快捷键不会排队卡死 |
| 记事本复用 | 写 `%Temp%\QuickOcr\result.txt`，同一进程复用窗口；内容没变只聚焦 | 避免刷出一排记事本 |
| 热键冲突 | 注册失败有日志、设置页提示更换 | 不静默失效，省掉「按了没反应」的排查 |
| 多屏 DPI | `PerMonitorV2` 感知，坐标按屏换算 | 混合 DPI 下框选区域不偏移 |
| 日志 | `%AppData%\QuickOcr\logs\QuickOcr_yyyyMMdd.log` 按天 | 免费工具里少见 |

「串行锁 + 丢弃」这个选择挺关键。换成排队，连按五次会依次识别五个相同的区域，用户等十秒；直接丢弃，语义是「你按得快，说明上一次不是你要的」。

## 一笔没算进表格的成本

Tesseract 的中文识别对**行内排版**比较敏感。框选时把正文和旁边的图标、行号一起框进去，结果里就会混进噪声字符。这不是 bug，是识别模型的固有行为：它不区分「你要的」和「画面里有的」。

所以这类工具的体验上限，一半取决于引擎，一半取决于「框得多准」。README 给的建议是「框选区域尽量只包含文字本身」——听着像废话，实际是使用这类工具最重要的一条技巧。

## 怎么判断一个免费工具能不能长期用

看完这个项目，我把它归纳成三个问题，比看 star 数有用：

1. **许可证是否三段都干净**：代码、引擎、模型数据。任何一段有「仅研究」「禁止商用」，就别往生产里放。
2. **失败时有没有出口**：引擎能不能换、接口约定是否公开、离线路径是否可手工兜底。出口越多，被单点卡死的概率越低。
3. **边界有没有写进文档**：精度不行、首次要联网、不能单文件发布——写出来的才叫边界，没写的是坑。

QuickOcr 三条都过。代价是 226 MB 和一堆得自己读代码的地方，但账算得过来：省下的是一笔按席位计的识别服务费，付出的是磁盘和一点耐心。
