## 现象

按设备分目录时，服务端从 UA 里解析型号，原本能拿到 `Mi 14`、`Pixel 7` 这样的字符串。某天开始，新机上解析出来的型号统一变成 `K`。

原因是 Android 的 UA 精简策略：`User-Agent` 里的设备型号被压缩成一个固定字符，用来降低指纹追踪面。**解析逻辑没变、输入变了**，于是所有新 Android 机都落进同一个目录。

## 新的一条路：Client Hints

浏览器提供了另一个接口，可以按需申请高熵字段：

```js
const hints = await navigator.userAgentData.getHighEntropyValues(['model']);
// hints.model → "Mi 14"
```

几个必须知道的限制：

- 只在安全上下文（HTTPS 或 `localhost`）可用，普通 HTTP 局域网访问拿不到；
- 不是所有浏览器都实现，`navigator.userAgentData` 可能整个不存在；
- 返回值也可能是空串。

所以不能把它当唯一来源，要设计**三级回退**：

```
userAgentData.model  →  UA 解析  →  "UnknownDevice"
```

## 同型号怎么区分

iOS 设备只报 `iPhone`，不报具体型号；两台小米 14 也会得到同一个字符串。若直接拿型号当目录名，多台同型号手机会混进同一个目录，按日期归档就分不清是谁传的。

做法是给每个浏览器实例一个随机尾缀，存在 `localStorage` 里保持稳定：

```
devices/
  小米14_7f3a/
  iPhone_a91c/
```

同一台手机反复访问始终落在同一个目录（`localStorage` 不变），不同手机互不干扰。取消限制时清掉这个键就会重新分配。

## 升级时的兼容

早期版本用的是「用户N」这种编号目录。新版本上线后：

- 已存在的旧目录**保留、不迁移**——迁移失败会造成历史文件丢失，风险远大于目录不整齐；
- 新设备一律走型号命名；
- 目录列表接口同时返回两类目录，前端照常展示。

## 一个容易忽略的点

即使型号来自浏览器 API，它依然是**客户端上报的数据**。所以型号拿到之后仍然要过一遍白名单与净化（见前一篇），不能因为"这是标准 API 返回值"就信任它。

## 教训

1. **浏览器上报的字段会变**。UA 精简这类变更不通知开发者，解析逻辑要有"识别不出来"的兜底分支，并且该分支不能静默合并到同一目录。
2. 能力探测要写成降级链，而不是假设某个 API 一定存在。
3. 同型号设备必须引入实例级区分（随机尾缀 + 本地存储），否则"按设备分组"在苹果设备上基本失效。
4. 目录结构调整时优先"新旧共存"，不要顺手迁移用户的历史文件。
