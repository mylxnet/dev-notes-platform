## 取证

调试库某个村组织，`再投资/羊鸡福` 这个二级科目：

```
opening_balance_cents = 1,683,445   （本金 ¥16,834.45）
balance_cents         = 1,733,948   （期初 + 收益 ¥505.03）
```

差额来自 txn #18：一笔 ¥505.03 的收入，`category_id` 指向了 `再投资/羊鸡福`。

对照长期投资：同一笔分红走的是 `投资收益/伊客拉穆`，容器正确。**长期对、再投资错。**

## 为什么会错

映射表里，两种收益被指向了不同容器：

```go
// receivable/repo.go
receiptKindToL1 := map[string]string{
    "dividend":          "投资收益",
    "reinvest_dividend": "再投资",   // ← 落进了本金科目
}
```

同时快速记账弹窗把 `autoBuildL1` 写死成 `投资收益`，允许选再投资单位——于是同一种业务，**收缴核销路径**和**手动记账路径**落进了两个不同的科目。

后果不只是显示错误：

- 再投资本金被永久虚增，页签「再投资总额」跟着错；
- 投资收益页签只读 `投资收益` 这个 L1，再投资收益**永远进不了 532 可分配池**；
- 想让「投资收益 / 类型 / 单位」三级并存，schema 又只支持 `level ∈ (1,2)`。

## 先分清三种口径

这是整件事的关键：页面上会同时出现三个"收益"，不定义清楚就会互相污染。

| 口径 | 数据来源 | 用途 | 与其他口径的关系 |
|---|---|---|---|
| **已收收益** | `receipt` 里 `dividend` / `reinvest_dividend` 下 `status='normal'` 的核销合计 | 页面展示、532 分配基数 | 权威值 |
| 入账现金 | `投资收益` / `再投资收益` 科目余额 | **仅用于对账** | ≤ 已收（抵销不入账） |
| 年预期收益 | 单位上的 `expectedReturnCents` | 长期/再投资页签 | 应计值，与实收无关 |

结论：**科目只负责两件事——存投出本金、做对账；不再作为收益展示源。**

## 被否决的三条路

| 方案 | 否决原因 |
|---|---|
| 只改展示，不动科目 | 再投资收益继续污染本金，账本身还是错的 |
| 在「投资收益」下加固定二级「再投资收益」 | 丢失单位维度，且该科目余额取不出来，对账提示没依据 |
| 做三级科目 | schema 只允许 `level 1/2`，改不动 |

## 采纳：新增一个一级科目 + 精确回填

1. 迁移新增预置 L1「再投资收益」（空容器，按单位名自动建同名 L2，与既有惯例一致）；
2. 入账容器从 `再投资` 改指 `再投资收益`；
3. 回填历史数据：用 `receipt(method='cash') ⨝ receivable(recv_kind='reinvest_dividend') → txn_id` 精确定位被错记的流水，先补建同名 L2，再把 `txn.category_id` 挪过去——**已作废的流水也一起挪**，否则本金科目下仍留着收益痕迹；
4. 前端 `autoBuildL1` 按所选单位类型动态选择，不再写死；
5. 532 分配基数改口径：`已收长期 + 已收再投资`。

迁移要幂等：每条建容器语句都带 `NOT EXISTS` 守卫，重复执行不重复建、不重复挪。

## 迁移后应当看到的数字

| 项 | 迁移前 | 迁移后 |
|---|---|---|
| 收益合计 | ¥11,000.00 | **¥11,505.03** |
| 532 可分配基数 | ¥11,000.00 | **¥11,505.03** |
| `再投资/羊鸡福` | 1,733,948 | **1,683,445**（本金归位） |
| `再投资收益/羊鸡福` | 不存在 | 50,503 |

## 两个必须提前讲清的副作用

1. **历史年度的 532 数字会变**。基数换口径后未分配额上升（本例 +¥505.03）。已生成的方案是快照字段，不回改，只影响新方案——这属于纠错，但需要业务方认可。
2. **直接入账、没挂应收的收益不在「已收」里**。这类钱进了科目余额却进不了分配池，所以页面上加了一条对账提示：差额 ≠ 0 时显示「有 X 元收益系直接入账未挂应收，未计入可分配」。

## 顺带记一个未修的缺陷

`再投资/甘肃琛兴科技` 期初 420,000、投出 550,000 → 余额 −130,000（负本金）。而页签金额列取 `Math.abs`，把这个负值"洗白"成 +¥1,300 计入总额。**负本金被绝对值掩盖**是独立的展示缺陷，与本方案无关，单开处理。
