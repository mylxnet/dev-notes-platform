## 现有入口为什么不够

应收模型很简单：`receivable` 有 `amount_cents` 和 `status(open/closed)`，核销记录 `receipt` 有 `method(cash/offset)`。派生量 `待收 = 应收 - 已核销`，结清自动 `closed`。

唯一能"抹掉"应收的入口是「作废应收单」，三条限制直接挡住了坏账：

| 限制 | 后果 |
|---|---|
| 只允许 `open` 且已收为 0 | 收过一部分的单，剩余变坏账 → 清不掉 |
| 直接删行 | 历史全没、不留痕、不可撤销 |
| 语义是"作废/重结" | 与"确实收不回来"的账务含义不同 |

结论：需要新增机制，而不是放宽旧入口。

## 方案：加第三种核销方式

核心决定只有一句：**坏账 = 一条 `receipt(method='writeoff', txn_id=NULL, note=原因)`**。

由此推导出全部行为：

| 议题 | 结论 | 推导理由 |
|---|---|---|
| 是否生成流水 | **不生成** | 确实没有钱进来，银行/科目/收支汇总都不该动 |
| 核销金额 | 后端**强制取剩余待收**，忽略前端传值 | 前端可改额就等于允许"部分坏账"，语义会糊 |
| 核销年度 | 仅允许本年度以前或未填年度 | 当年就认坏账不合业务常理，`BAD_DEBT_YEAR_NOT_ALLOWED` |
| 原因 | 必填，`BAD_DEBT_NOTE_REQUIRED` | 无原因的核销无法解释 |
| 可逆性 | 允许撤销 | 复用现有「作废核销」：`closed → open`、待收恢复 |
| 入口位置 | 设置页独立功能 | 低频 + 危险操作，与日常核销动线分离 |

schema 改动只有一处：把 `receipt.method` 的 CHECK 从 `('cash','offset')` 放宽到三值。沿用既有的「`PRAGMA defer_foreign_keys=ON` + 重建表」迁移法，保留原 id，外键约束不受影响。

撤销是零开发：`VoidReceipt` 本来就只对 `cash` 连带作废流水，`writeoff` 天然不碰流水，回退逻辑自动成立。

## 最容易出错的不是后端，是"哪些单还该显示"

坏账单一旦 `closed`，就会从往来单位的欠款合计里消失（那里只统计 `open`）——这是对的，但页面上的明细列表如果也只按 `open` 过滤，用户点开坏账统计卡会看到"有 3 笔坏账"却一条明细都没有，**明细与合计对不上**。

所以定了一条显示集规则，所有页面共用：

> 一条应收单出现在正常页面的条件：**非坏账单**，**或**坏账单但实际现金已收 > 0。

含义是：

- **部分坏账**（收到过一部分现金）→ 正常页面显示，行内标「坏账」，按 应收 / 已收 / 坏账 / 未收 四栏呈现；
- **全额坏账**（一分没收）→ 正常页面完全剔除，只在坏账清单页归档。

这样「合计 = 明细之和」恒成立。代价是撤销入口不能放在正常页面（单子已经不在那了），必须迁到坏账清单页——一个独立路由页面，列出全部坏账单（含全额坏账），可查可撤销。

## 不变式与边界

状态机保持不变：`已核销（全部 normal）== 应收 → closed`；作废任一核销后重新汇总，未结清则退回 `open`。`sumPaidTx` 保持"全部 normal 核销"口径不变，避免波及既有状态机。

必须覆盖的边界：

| 场景 | 预期 |
|---|---|
| 越权（他人组织应收单） | 404 |
| 已结清单再核销 | `RECEIVABLE_CLOSED` |
| 并发双击 | 幂等，只生效一次 |
| 部分已收后坏账 | 坏账额 = 剩余待收，不是整单金额 |
| 撤销后再核销 | 可重现，状态正确 |
| 核销本年度应收 | 拒绝 |

## 影响面

**不变**：银行存款、科目余额、收支汇总、导出。
**变化**：该单待收归零、单位欠款合计下降（单子转 `closed` 后被排除）。

这与"坏账确实收不到钱"的现实一致——不制造虚假的现金流入，是这套设计的底线。
